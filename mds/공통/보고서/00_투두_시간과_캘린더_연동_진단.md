- **버전**: 공통, 현행 코드 진단과 개선 설계이며 앱 결과 버전을 새로 채택하지 않는다.

## 결론
- **직접 원인 확정**: 투두 시간은 앱에 저장되지만 캘린더로 보내는 생성 및 수정 경로가 시간 필드를 지원하지 않는다.
  - 신규 투두는 시간이 있어도 종일 일정으로 생성한다.
  - 연결된 투두의 시간 변경과 시간 삭제는 캘린더 수정 요청으로 이어지지 않는다.
  - 안드로이드와 iOS 사본에 같은 문제가 존재한다.
- **추가 결함 확인**: 시간 가져오기가 외부에서 처음 가져온 일정에만 적용되고, 시간 충돌은 앱 변경 여부를 비교하지 않는다.
- **안내 결함 확인**: 권한 부족이나 생성 오류로 실제 반영이 없어도 수동 동기화는 성공 문구를 표시할 수 있다.
- **검증 결과**: 루트 기존 관련 테스트 36건 통과, 별도 진단 8건에서 현재 결함 동작 재현. iOS 코드 사본에서도 같은 기존 36건과 진단 8건, 합계 44건 실행 완료.
  - 진단 테스트는 잘못된 현재 동작을 관찰하는 테스트다. 테스트 통과가 시간 연동 정상이나 수정 완료를 뜻하지 않는다.
  - iOS 사본의 Flutter 테스트이며 iOS 네이티브 실행이나 실기기 계정 동기화 검증은 아니다.

## 원인 상세
### 1. 시간이 있는 새 투두도 종일로 내보냄
- 예: 내일 `14:30 회의`를 저장하면 앱에는 `14:30`이 남지만 캘린더에는 내일의 종일 `회의`가 만들어진다.
- 저장소는 `create(calendarId, title, day)`만 호출한다.
- 서비스는 시간 인자 자체가 없으며 전달받은 날짜에 시각이 포함되어도 연, 월, 일만 추출한다.
- 마지막 동기화 기준인 `_Link`도 앱 생성 시 시간을 저장하지 않는다.
- 따라서 기다리기, 다시 동기화, 앱 재실행만으로 시간 일정이 되지 않는다.

### 2. 시간 수정과 종일 전환을 비교하지 않음
- 기존 투두의 `14:30 → 16:00` 변경은 로컬 저장만 바뀐다.
- `종일 → 시간 지정`, `시간 지정 → 종일`도 전송 경로가 없다.
- 수정 서비스 역시 제목과 날짜만 받으며 날짜를 보내면 종일로 고정한다.
- 생성 경로만 고치면 기존 투두의 수정과 날짜 이동에서 다시 문제가 생긴다.

### 3. 시간 동기화가 출처별로 다르고 충돌 규칙이 빠짐
- 외부에서 처음 가져온 일정:
  - 처음 가져올 때 시간은 저장된다.
  - 외부 시간 변경도 가져온다.
  - 앱에서 시간을 바꾸면 외부 캘린더로 보내지 않는다.
- 앱에서 처음 만든 일정:
  - 외부에서 종일 일정을 시간 일정으로 바꾸어도 `imported == false`여서 시간을 가져오지 않는다.
- 충돌:
  - 마지막 기준 `14:30`, 앱 `15:00`, 외부 `16:00`이면 앱은 `16:00`으로 덮인다.
  - 제목과 날짜에 쓰는 세 갈래 비교가 시간에는 없다.
- 날짜도 연관된다:
  - `dateIsPushable = !link.imported && ev.allDay`여서 가져온 일정 또는 시간 일정의 날짜를 앱에서 바꿔도 외부에 보내지 않는다.
  - 앱과 외부 날짜가 어긋난 상태가 유지될 수 있다.
  - 날짜와 시간을 따로 고치기보다 일정 전체 변경 규칙을 정해야 한다.

### 4. 실제 동기화 실패가 성공으로 보일 수 있음
- 권한이 없으면 `_sync()`는 결과 정보 없이 종료한다.
- 개별 생성과 수정 오류는 로그만 출력하고 계속하며 `sync()`도 예외를 로그로 처리한다.
- 설정 화면은 `await vm.syncCalendarNow()` 뒤에 무조건 `캘린더와 맞췄어요`를 표시한다.
- 근거: [저장소](../../../lib/data/repositories/calendar_repository.dart#L159), [설정 화면](../../../lib/ui/features/settings/views/settings_screen.dart#L145).
- 연결 개수는 과거 연결 상태의 수이며 현재 동기화 성공 여부를 증명하지 않는다.

## 확인된 범위와 미확인 사항
- Android의 `READ_CALENDAR`, `WRITE_CALENDAR` 선언과 iOS의 캘린더 사용 설명 키는 존재한다.
  - 근거: [AndroidManifest.xml](../../../android/app/src/main/AndroidManifest.xml#L3), [Info.plist](../../../SUnDo-ios/ios/Runner/Info.plist#L38).
  - 실제 사용자의 권한 허용 여부와 계정 상태는 확인하지 않았다.
- 플러그인은 시작, 종료 시각을 받는 시간 일정 생성을 지원한다.
  - [공식 사용 문서](https://github.com/bullet-to/device_calendar_plus/blob/main/packages/device_calendar_plus/README.md)의 생성 예제와 날짜 계약, 로컬에 설치된 0.10.2 API를 대조했다.
  - 설치된 API의 `createEvent`에는 `startDate`, `endDate`, `isAllDay`, `timeZone` 인자가 있다. 라이브러리를 바꾸지 않고 앱 계층을 개선할 수 있다.
  - Context7에는 해당 패키지의 정확한 항목이 없어 공식 저장소와 설치된 소스로 확인했다.
- 기기 캘린더에 쓰는 방식이며 Google/삼성 서버 API를 직접 호출하지 않는다. 계정 전파 지연은 별도 검증 대상이다.
- 시간대가 이번 증상의 직접 원인이라는 증거는 없다.
  - 설치된 `Event.fromMap`은 로컬 `DateTime`을 만들고 현재 서비스는 그 날짜와 시각을 읽는다.
  - 자정, 시간대 변경, 해외 일정과 DST는 개선 후 회귀 검증에 포함한다.
- 앱 내부 통계 캘린더:
  - 같은 Journal 저장소를 구독하고 시간순 목록을 구성한다.
  - 월간 격자는 완료 개수를 표시하며 시간은 날짜 상세 목록에 표시한다.
  - 근거: [stats_view_model.dart](../../../lib/ui/features/stats/view_models/stats_view_model.dart#L111), [stats_screen.dart](../../../lib/ui/features/stats/views/stats_screen.dart#L349).
  - 사용자가 말한 캘린더가 앱 내부 월간 격자라면 시간별 일정표가 없는 표시 방식도 구분해야 한다.

## 개선안과 적용 순서
### P0. 앱 소유 일정의 시간 쓰기부터 완성
- 생성과 수정 서비스에 시작, 종료, 종일 상태를 명시적으로 전달한다.
  - 시간이 있으면 날짜와 `HH:mm`을 결합하고 `isAllDay: false`로 생성한다.
  - 시간이 없으면 종일 일정으로 만들고 종료를 다음 날 0시로 둔다.
  - 수정에서 `변경하지 않음`과 `빈 시간으로 지워 종일로 전환`을 구분한다.
- Todo에는 종료 시간이 없으므로 신규 일정의 기본 길이가 필요하다.
  - 권고안: 신규 앱 일정은 우선 60분, 추후 설정 가능하게 한다.
  - **제안이며 사용자 확정값은 아니다.** 기존 외부 일정의 길이를 이 값으로 덮지 않는다.
- `_Link.time`을 앱 생성 일정에도 저장하고 시간 변경과 삭제를 동기화 대상으로 처리한다.
- 제목이나 완료만 수정할 때 기존 시작, 종료, 종일, 시간대는 유지한다.

### P0. 기존에 잘못 만들어진 종일 일정 보정
- 기존 앱 소유 연결 중 투두에 시간이 있는 항목을 식별한다.
- 같은 이벤트 ID를 `update`하여 시간을 붙이고 성공한 항목만 기준값을 갱신한다.
- 재생성이나 전체 삭제를 기본 복구 수단으로 사용하지 않는다.
- 주의:
  - 기존 `link.time`이 비어 있다고 앱이 시간 삭제를 요청했다고 판단하면 안 된다.
  - 양쪽 내용이 이미 다르면 자동 덮어쓰기보다 충돌 항목을 표시하고 결정한다.
  - 재실행 시 중복 생성 없이 수렴해야 한다.

### P1. 날짜, 시간, 종일을 묶어 충돌 처리
- 일정 비교 단위를 `(날짜, 시각, 종일 여부)`로 정하고 마지막 성공 상태를 기준값으로 저장한다.
- 앱만 변경하면 보내고, 외부만 변경하면 가져오며, 둘 다 바뀌면 정한 충돌 정책을 적용한다.
  - 앱 소유 일정은 기존 제목/날짜의 앱 우선 규칙과 일관되게 처리하는 방안을 권고한다.
  - 외부 소유 일정은 보호 정책을 분리한다.
- `CalendarEvent`에 현재 누락된 종료 시각과 시간대, 필요한 편집 가능 정보를 보존한다.
- 외부 일정 편집 정책 권고:
  - 읽기 전용 캘린더는 제목과 완료를 포함한 외부 쓰기를 막고 이유를 표시한다.
  - 외부 일정의 날짜와 시간은 기본적으로 원본을 따른다.
  - 앱에서 옮기기를 제공하려면 허용 동작으로 명확히 구분하고 기존 길이와 메타데이터를 보존한다.
  - 전송하지 않는 필드는 앱에서 편집해도 된다고 보이지 않도록 편집 제약 또는 사본 만들기를 제공한다.

### P1. 동기화 결과를 화면에 전달
- `SyncResult`에 성공, 부분 실패, 권한 부족, 연동 꺼짐과 처리 수를 담는다.
- 마지막 시도와 성공 시각, 실패 원인을 저장하거나 UI 상태로 노출한다.
- 수동 동기화 안내는 반환 결과에 따라 표시한다.
  - 예: `3개 반영했어요`, `2개 반영, 1개 실패`, `캘린더 권한을 허용해 주세요`.
- 자동 동기화는 항목별 실패를 격리하되 실패 상태와 재시도 대상을 유지한다.
- 로그에는 단계와 오류 코드, 필요한 연결 ID만 남기고 투두 제목 같은 개인 내용은 최소화한다.

### P2. 플랫폼별 검증과 이후 유지
- Android/iOS 두 사본의 서비스, 저장소, 모델, 화면과 테스트를 함께 변경한다.
- 검증 단계:
  - 실제 서비스 호출 인자의 단위 테스트로 시작, 종료, 종일 값을 확인한다.
  - 저장소 회귀 테스트로 비교와 기존 링크 보정을 확인한다.
  - Android 기기 캘린더와 iOS EventKit에서 읽어 되돌려 확인한다.
  - 마지막으로 실제 Google/삼성 계정 전파와 권한 변경을 확인한다.
- 캘린더 권한이나 계정 동기화 문제는 코드상 시간 누락을 고친 뒤 별도 검증한다.

## 수정 완료 판정 기준
- [ ] 시간 있는 신규 투두가 동일 날짜와 시각의 시간 일정으로 생성된다.
- [ ] 시간 수정, 시간 삭제, 종일 전환과 날짜 변경이 정상 반영된다.
- [ ] 날짜만 변경하거나 완료만 바꿔도 기존 시간이 사라지지 않는다.
- [ ] 기존 앱 소유 종일 일정을 이벤트 ID와 개수를 유지하며 보정한다.
- [ ] 외부 생성 및 앱 생성 일정 모두 허용된 외부 시간 변경을 가져온다.
- [ ] 동시 변경과 동기화 도중 앱 편집을 정한 충돌 정책대로 처리한다.
- [ ] 외부 일정의 길이, 시간대와 편집 제약을 보존한다.
- [ ] 권한 부족과 부분 실패에서 성공 안내를 표시하지 않는다.
- [ ] 반복 동기화, 앱 재시작, 자정과 시간대 변경에도 중복이나 시간 유실이 없다.
- [ ] Android/iOS의 실제 캘린더 읽기 결과와 계정 전파를 확인한다.

## 재현 방법
- 기존 검증: 프로젝트 루트에서 다음 명령을 실행한다.
```sh
flutter test test/data/calendar_repository_test.dart test/ui/todo_time_and_manage_test.dart test/ui/todos_view_model_test.dart --reporter expanded
```
- 별도 진단:
  - 아래 Dart 코드는 기존 `calendar_repository_test.dart`에서 `void main() {` 앞의 import와 가짜 서비스/도우미 선언에 이어 붙인 임시 테스트로 실행했다.
  - 임시 파일은 각 앱의 `test/data/_calendar_time_diagnosis_test.dart`로 생성했다. 조사 후 삭제했으며 앱 또는 기존 테스트 파일은 수정하지 않았다.
  - 진단 파일의 전체 조립 방식은 다음과 같다. Python 코드의 `probes`에는 아래 Dart 블록을 문자열로 넣는다.
```python
from pathlib import Path
fixture = Path('test/data/calendar_repository_test.dart').read_text().split('void main() {', 1)[0]
Path('test/data/_calendar_time_diagnosis_test.dart').write_text(fixture + probes)
```
```sh
flutter test --no-pub test/data/_calendar_time_diagnosis_test.dart --reporter expanded
```
- iOS 사본: 같은 임시 파일을 `SUnDo-ios/test/data/`에 두고 `SUnDo-ios`에서 기존 3개 파일과 임시 파일을 함께 실행한다.
- 진단 테스트 원문:
```dart
class _RecordingPlugin implements DeviceCalendar {
  final List<Invocation> calls = [];
  @override
  dynamic noSuchMethod(Invocation call) {
    calls.add(call);
    if (call.memberName == #createEvent) return Future<String>.value('native-probe');
    if (call.memberName == #updateEvent) return Future<void>.value();
    throw UnsupportedError('Unexpected plugin call: ${call.memberName}');
  }
}

class _FailingCalendar extends _FakeCalendar {
  @override
  Future<String> create({required String calendarId, required String title, required DateTime day}) async {
    throw Exception('diagnostic-create-failure');
  }
}

void main() {
  test('P1 실제 서비스가 시각을 자정으로 바꾸고 종일로 전송', () async {
    final plugin = _RecordingPlugin();
    final service = CalendarService(plugin: plugin);
    await service.create(calendarId: 'c1', title: '회의', day: DateTime(2026, 10, 21, 14, 30));
    final args = plugin.calls.single.namedArguments;
    expect(args[#startDate], DateTime(2026, 10, 21));
    expect(args[#endDate], DateTime(2026, 10, 22));
    expect(args[#isAllDay], true);
    print('P1 start=${args[#startDate]} end=${args[#endDate]} allDay=${args[#isAllDay]}');
  });
  test('P2 시간 있는 신규 투두도 종일 일정 생성', () async {
    final s = await _setup();
    await s.repo.enable(_cal);
    await s.journal.addTodo('회의', _future(1), time: '14:30');
    await s.repo.sync();
    expect(s.journal.todos.single.time, '14:30');
    expect(s.fake.events.values.single.allDay, true);
    expect(s.fake.events.values.single.time, '');
    print('P2 todoTime=${s.journal.todos.single.time} eventTime="${s.fake.events.values.single.time}" allDay=${s.fake.events.values.single.allDay}');
  });
  test('P3 시간만 수정하면 캘린더 수정 호출 없음', () async {
    final s = await _setup();
    await s.repo.enable(_cal);
    final t = await s.journal.addTodo('회의', _future(1), time: '14:30');
    await s.repo.sync();
    s.fake.log.clear();
    await s.journal.updateTodo(t.copyWith(time: '16:00'));
    await s.repo.sync();
    expect(s.fake.log, isEmpty);
    expect(s.journal.todos.single.time, '16:00');
    print('P3 todoTime=${s.journal.todos.single.time} calendarWrites=${s.fake.log.length}');
  });
  test('P4 가져온 일정의 앱 시간 수정은 무시되고 양쪽 시간 변경 시 외부 값으로 덮임', () async {
    final s = await _setup();
    await s.repo.enable(_cal);
    s.fake.events['external'] = _Ev('외부 회의', parseDateKey(_future(1)), time: '14:30')..allDay = false;
    await s.repo.sync();
    await s.journal.updateTodo(s.journal.todos.single.copyWith(time: '15:00'));
    await s.repo.sync();
    expect(s.fake.events['external']!.time, '14:30');
    expect(s.journal.todos.single.time, '15:00');
    s.fake.events['external']!.time = '16:00';
    await s.repo.sync();
    expect(s.journal.todos.single.time, '16:00');
    print('P4 appEdit=15:00 remoteBefore=14:30 remoteAfter=16:00 todoAfter=${s.journal.todos.single.time}');
  });
  test('P5 앱 생성 일정을 외부에서 시간 일정으로 전환해도 가져오지 않음', () async {
    final s = await _setup();
    await s.repo.enable(_cal);
    await s.journal.addTodo('회의', _future(1));
    await s.repo.sync();
    s.fake.events.values.single..allDay = false..time = '17:00';
    await s.repo.sync();
    expect(s.journal.todos.single.time, '');
    print('P5 remoteTime=17:00 todoTime="${s.journal.todos.single.time}"');
  });
  test('P6 권한이 없어도 동기화 Future가 정상 종료', () async {
    final s = await _setup();
    await s.repo.enable(_cal);
    await s.journal.addTodo('회의', _future(1));
    s.fake.permission = false;
    await expectLater(s.repo.sync(), completes);
    expect(s.fake.events, isEmpty);
    print('P6 permission=false syncFuture=completed events=${s.fake.events.length}');
  });
  test('P7 생성 오류가 있어도 동기화 Future가 정상 종료', () async {
    SharedPreferences.setMockInitialValues({});
    final store = await StorageService.create();
    final journal = JournalRepository(store);
    await journal.load();
    final repo = CalendarRepository(store, _FailingCalendar(), journal);
    await repo.load();
    await repo.enable(_cal);
    await journal.addTodo('회의', _future(1));
    await expectLater(repo.sync(), completes);
    expect(repo.linkedCount, 0);
    print('P7 createFailure=true syncFuture=completed linkedCount=${repo.linkedCount}');
  });
  test('P8 가져온 시간 일정의 날짜 수정도 캘린더에 미반영', () async {
    final s = await _setup();
    await s.repo.enable(_cal);
    final original = _future(1);
    s.fake.events['external'] = _Ev('회의', parseDateKey(original), time: '14:30')..allDay = false;
    await s.repo.sync();
    await s.journal.updateTodo(s.journal.todos.single.copyWith(date: _future(2)));
    await s.repo.sync();
    expect(dateKey(s.fake.events['external']!.day), original);
    expect(s.journal.todos.single.date, _future(2));
    print('P8 todoDate=${s.journal.todos.single.date} eventDate=${dateKey(s.fake.events['external']!.day)}');
  });
}
```
