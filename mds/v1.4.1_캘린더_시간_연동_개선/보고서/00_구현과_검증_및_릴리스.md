- **버전**: v1.4.1 (폴더 v1.4.1_캘린더_시간_연동_개선, 앱 1.4.1+8)

## 목표와 실행 계획
- 목표: 진단된 시간 연동 누락과 오류 안내를 해결하고 설치 가능한 APK를 기존 GitHub Release 방식으로 배포한다.
- 접근: 데이터와 UI 병렬 구현, 네이티브 통합 테스트, 부모 코드 검토, 전체 검증, 서명 확인, iOS CI, 릴리스 순서.
- 검증: 시간 생성, 수정, 삭제, 종일 전환, 기존 연결 보정, 외부 일정과 충돌, 실패 복구, 동일 서명 및 배포 자산 해시.

## 구현 상태
- 데이터 계층과 UI 구현 완료, 부모가 전체 diff를 검토하고 경합 보호와 릴리스 배선을 통합했다.
- UI 동기화 결과별 안내와 읽기 전용 시간 편집 보호 구현, 루트 관련 27건 통과.
- Journal 필드 단위 갱신과 조건부 삭제를 추가해 최신 완료, 숨김, 시간 정보를 보존하고 삭제된 항목을 되살리지 않는다.
- Android API35 실제 캘린더 통합 테스트는 runner 연결 문제를 조사하며 실행 중이다. 앱 오류로 판정하지 않는다.

## 정책
- 신규 시간 일정 기본 60분, 시간 없음은 종일이다.
- 쓰기 가능한 외부 일정의 날짜와 시간 편집을 허용하고 기존 길이 및 메타데이터를 유지한다.
- 일정 비교는 날짜와 시간을 함께 처리하고 동시 변경은 앱 우선이다.
- 레거시 종일 연결은 동일 이벤트 ID로 보정하며 양쪽이 이미 다르면 충돌 안내를 남긴다.
- 읽기 전용 일정에는 쓰지 않는다.

## 검증과 재현
- 루트와 SUnDo-ios 각각 `flutter analyze --no-fatal-infos`, `flutter test`를 수행한다.
- Android 네이티브 검증: `flutter test integration_test/01_calendar_sync_test.dart -d emulator-5554`.
  - 먼저 테스트 앱에 READ_CALENDAR와 WRITE_CALENDAR를 부여한다.
  - SharedPreferences는 mock으로 격리하고 임시 고유 캘린더만 생성과 삭제한다.
- iOS 네이티브 검증: 기존 ios-simulator 워크플로에 캘린더 권한 준비 단계를 추가하고 통합 테스트를 실행한다.
- 릴리스 빌드: `flutter build apk --release`.
- 로컬 전체 테스트: 루트 149건, iOS 사본 149건 통과.
- 루트 분석: 오류와 경고 0, 기존 info 22개(중첩 iOS 사본 포함). 신규 번호 파일은 파일명 규칙의 lint 예외를 명시했다.
- 부모 보완 후 UI/Journal 관련 13건 통과.
- 네이티브 테스트와 CI 결과는 완료 후 실제 실행 URL과 함께 갱신한다.

## 부모 최종 코드 검토
- 전체 변경 diff와 서비스 호출, 저장소 비교, UI 배선 및 회귀 테스트를 직접 확인했다.
- 검토로 보완한 항목:
  - 읽기 전용 및 레거시 충돌의 예외를 결과로 반환하고 오류 후 큐가 다음 동기화를 수행하게 했다.
  - 원격 삭제와 이미 저장한 로컬 편집이 충돌할 때 앱 값을 보존하고 새 일정에 연결한다.
  - 결과 저장 실패는 마지막 성공 시각을 갱신하지 않도록 복원한다.
  - 레거시 충돌과 읽기 전용 제약의 해결 방법을 결과 detail과 UI 안내에 보존한다.
  - 편집 중 완료와 숨김 상태를 덮지 않고 삭제된 투두는 재생성하지 않는다.
  - 캘린더 편집 가능 정보가 바뀌면 열려 있는 투두 편집 화면도 갱신한다.
- 서비스 get과 update는 OS가 원자적 조건부 쓰기를 제공하지 않아, 그 사이 외부 앱이 같은 일정의 길이를 바꾸는 순간까지 충돌을 보장하지는 않는다.
- 원격 일정 생성 직후 저장소가 영구 실패하고 앱이 종료되는 경우의 분산 트랜잭션 보장은 기존 저장 구조의 한계로 남는다.
