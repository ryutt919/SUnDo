## 최종 동작
- 시간이 있는 투두는 날짜와 HH:mm을 함께 보내고 기본60분 일정으로 생성한다.
- 시간 수정, 시간 삭제와 종일 전환, 날짜 이동을 같은 이벤트 ID로 반영한다.
- 날짜와 시간은 마지막 성공값을 기준으로 함께 비교한다.
  - 앱만 변경하면 보내고 외부만 변경하면 가져온다.
  - 같은 일정의 양쪽 변경은 앱이 우선한다.
  - 원격 삭제와 로컬 편집이 충돌하면 로컬 투두를 보존하고 새 일정에 연결한다.
- 기존 종일 연결 중 시간 기준이 없는 앱 생성 일정은 같은 ID로 보정한다.
  - 기존 양쪽 일정이 이미 다르면 자동 추정으로 덮지 않고 확인 방법을 안내한다.
  - schema2의 사용자가 꺼 둔 새 일정 가져오기 설정을 다시 켜지 않는다.
- 쓰기 가능한 외부 일정의 날짜와 시간도 편집할 수 있으며 원래 길이를 유지한다.
  - 제목만 수정할 때 시작/종료와 시간대, 설명, 장소, 알림은 수정하지 않는다.
  - 읽기 전용 일정에는 쓰지 않으며 날짜/시간 버튼을 비활성화한다.
  - 제목 앞뒤 공백만 다르면 변경으로 오인하지 않고 실제 사용자 제목 수정은 감지한다.
- 동기화 결과는 성공, 부분 실패, 권한 부족, 연동 꺼짐, 실패로 구분한다.
  - 처리 수, 실패 원인과 마지막 성공 시각을 표시하고 일반 오류에 투두 제목을 노출하지 않는다.
  - 레거시 충돌과 읽기 전용 제약은 원인과 필요한 조치를 안내한다.
  - 결과 저장 실패는 마지막 성공 시각을 갱신하지 않으며 다음 실행에서 재시도한다.
- Journal의 필드 patch와 조건부 삭제가 기다리는 동안 바뀐 완료, 숨김, 일정 상태를 보존한다.
  - 삭제된 투두를 편집 저장으로 되살리지 않는다.
  - 캘린더 편집 가능 상태가 바뀌면 열려 있는 편집 화면도 갱신한다.

- 실제 Galaxy와 Google/삼성 계정 서버 전파는 확인하지 않았다. Android API35 기기 캘린더와 iOS 시뮬레이터 EventKit까지 검증했다.

- 원격 생성 직후 저장소가 영구 실패하고 앱이 종료되는 경우의 분산 트랜잭션 보장은 기존 저장 구조의 한계로 남는다.
